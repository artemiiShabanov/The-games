# Дебаг-меню и тестовые сцены

**Status:** Building (каркас в #20, разделы систем по их задачам) · **Issue:** #20

## Цель

Любую систему игры можно открыть за три секунды в нужном состоянии, не проходя забег: нужную
мини-игру с нужной сложностью, демку с нужным набором багов, экран с нужными числами. Меню
живёт весь проект и растёт вместе с ним: каждая новая система регистрирует в нём свои ручки
в той же задаче, где появляется.

## Поведение

- **Открытие.** F1 в любом месте игры, поверх текущей сцены, дерево на паузе. Esc или F1
  закрывает. Флаг `--debug` открывает меню сразу при старте, `--scene=<id>` запускает тестовую
  сцену без меню. В релизной сборке меню и папка `debug/` исключены экспортом.
- **Вид.** Слева список разделов, справа содержимое раздела, стрелки и A, B как в игре, плюс
  мышь. Моноширинный шрифт, цвета оболочки, но без претензии на стиль. Последний открытый
  раздел и введённые значения помнятся в `user://debug.cfg`.
- **Разделы** в v1, остальные добавляются по мере задач:
  - *Сцены*: все тестовые сцены из `res://debug/scenes/`, найденные сканированием папки,
    подпись из имени файла; запуск заменяет текущую сцену, пункт «В игру» возвращает в главную.
  - *Мини-игры*: любая `MinigameDef` из `resources/minigames/`, ползунок `t` 0..1, поле сида,
    галка «зациклить» (после результата та же мини-игра с новым сидом), запуск. После результата
    в углу: успех или провал, сколько длилась, какой сид.
  - *Демки*: жанр, технология, сид, галочки багов из `BugCatalog`, запуск. Источник помечается
    как `debug`, итог возвращает в меню.
  - *Состояние*: дамп текущего забега и записи игры; с M1 правка денег, номера релиза,
    репутации, принудительная вставка меты.
  - *Переключатели*: бот всегда выигрывает, бот всегда проигрывает, скорость времени ×0.25, ×1,
    ×4, FPS и время кадра, хитбоксы, без звука, пропуск карточек и анимаций студии.
  - *Автотест*: прогнать бота на N спринтов прямо здесь, скриншот в `debug/playtest/`.
- **Горячие клавиши** вне меню: F1 меню, F2 оверлей FPS, F3 цикл скорости времени, F5 перезапуск
  текущей сцены, F9 скриншот в `debug/playtest/`. Больше не заводим, остальное через меню.

## Данные

- Автолоад `Debug` (`debug/debug.gd`), один на проект. Реестр, через который системы
  добавляют ручки, не трогая сцену меню:
  - `Debug.add_action(section: StringName, label: String, fn: Callable)`
  - `Debug.add_toggle(section, label, get: Callable, set: Callable)`
  - `Debug.add_number(section, label, get, set, min, max, step)`
  - `Debug.add_choice(section, label, options: Array, get, set)`
  - `Debug.watch(label, get: Callable)` — строка в оверлее F2.
- Системы регистрируются в `_ready` с проверкой `OS.is_debug_build()`; в релизе вызовы
  превращаются в пустые.
- Состояние: `user://debug.cfg` — раздел, последние значения полей, включённые переключатели.
- Тюнинг не нужен; горячие клавиши в `project.godot` как действия `debug_*`.

## Тестовые сцены

- Лежат только в `thegames/debug/scenes/`, по одной на вопрос: `<тема>_test.tscn` плюс
  `<тема>_test.gd`. Продовые сцены в `scenes/` на них никогда не ссылаются, обратное можно.
- Каждая запускается сама по себе (F6 в редакторе), пишет в углу, что проверяет и какие
  клавиши работают, и не требует состояния забега: что нужно, создаёт сама или берёт из меню.
- Примеры по вехам: `sprint_runner_test` (8 спринтов подряд ботом), `level_gen_test` (сто
  уровней из сидов рядом, карта проходимости), `bug_showcase_test` (демка с одним багом по
  выбору, все баги по очереди), `palette_test` (четыре акцентных слота по палитрам),
  `success_model_test` (кривая хвоста по формулам рядом с числами из `tools/model_run.py`).
- `debug/playtest/` для скриншотов, логов и сохранений плейтестов, в gitignore.

## Крайние случаи и вне скоупа

- Меню открыто во время мини-игры: таймер мини-игры стоит на паузе вместе с деревом,
  закрытие продолжает её; это единственная пауза, которая у мини-игр есть.
- Автотест не зависит от меню: `--auto-test` работает и без автолоада, через те же ручки
  бота.
- Вне скоупа: редактор уровней, инспектор нод (есть в редакторе Godot), консоль с командами,
  удалённое управление.
